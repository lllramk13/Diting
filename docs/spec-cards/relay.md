# 规格卡：Relay 首页

- 路由：`/relay`
- 权限：`[公开]`
- 批次：第 1 批（公开侧）

## 1. 给谁看

1. **找补丁的玩家**（流量大头）：想知道有什么游戏的汉化、进展如何、能不能下载。
2. **潜在贡献者**：被"我也想参与汉化"吸引，教程是给他们的。
3. **回访的成员**：只想尽快进工作台，别挡路。

这页的唯一任务：让三种人在 3 秒内找到自己的下一跳。任何不服务这三跳的内容不上首屏。

## 2. 从哪进，往哪出

进入：主站首页 Relay 入口、直接 URL、搜索引擎、项目页向上返回。

出口：

```text
├─ 一句话介绍 + 视觉锤        → 定调，不出口
├─ 公开项目卡片               → /relay/projects/:slug
├─ 最近发布                   → /relay/projects/:slug/releases/:version
├─ 互动教程入口               → /relay/tutorial
├─ 登录 / 打开工作台          → /auth/login 或 /relay/workspace
└─ 页脚：支持 Relay、返回主站  → /relay/support、/
```

## 3. 核心数据

- 公开项目列表：封面、名称、平台、目标语言、翻译/审核进度、状态
- 最近发布：版本号、日期、所属项目

两个查询都是纯公开数据，RLS 最简单一档。全平台聚合统计不做（见「砍掉的」）。

## 4. 主要操作

只读页，零写操作。点进项目 / 开始教程 / 登录或进工作台。

## 5. 空态

MVP 现实：一个项目、可能零发布。因此不按项目网格设计，**设计成单项目主推位**——一个大卡片直接展示该项目；发布区为空时显示「首个版本制作中 + 当前进度」。项目多了再演化成网格。

## 6. 无权限态

不存在，全页公开。唯一条件渲染：右上角未登录显示「登录」，已登录显示「打开工作台」。

## 砍掉的（对照 page-tree 第 4 节原清单）

- **当前协作数据**（全平台统计）：单项目时与项目进度重复，还要多写聚合查询。≥3 个项目后再加。
- **平台赞助**：页脚链接即可，不占正文区块。
