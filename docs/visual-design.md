# Visual Design

状态：骨架。设计系统阶段填充（见 roadmap，位于线框之后）。

职责：设计系统、视觉模式、交互与响应式规范的真源。

## 待写章节

1. **设计原则**：复古科幻终端气质 × 现代可用性；观赏模式只能增加气氛，不能降低可用性。
2. **实用模式 / 观赏模式**：两种模式的实现边界，对照 README「视觉原则」——相同的信息结构、按钮位置和操作逻辑。
3. **Design Tokens**：颜色、字体、字号、间距、圆角、辉光与扫描线参数；两种模式共享一套 token，观赏模式只叠加效果层。
4. **核心组件规范**：按钮、输入、表格、状态标签、进度、弹窗、Toast。
5. **响应式断点与移动端行为**：导航抽屉、编辑器在窄屏下的布局。
6. **可访问性**：对比度底线、键盘操作、焦点样式、`prefers-reduced-motion`。

## 参考

- [pxpush.com](https://pxpush.com/)：编号语言（Nº001）、重复标头造节奏、靠排版而非特效撑场面。适用于主站与 Relay 公开页的气质，不适用于工作区信息密度。
- [c2mtl.koki-kiko.com](https://c2mtl.koki-kiko.com/)：开场揭示序列（加载 → 大字排版逐层出现）。与 DotField 的点阵汇聚开场同一方向。边界：仅用于主站首页与 /relay 首页；可跳过、每会话一次；实用模式与 `prefers-reduced-motion` 下不播；属观赏模式阶段，切片跑通前不实现。
- [orage.studio](https://orage.studio/)：与 DITING 气质最接近的整站范例——模拟控制台加载序列、黑白单色、001 编号、把技术信息（编码参数、时间码）当排版素材。启示：终端感靠真实数据的仪式化排版，不靠故障特效；DITING 的条目 ID、控制码、进度、版本号都是同类素材。
