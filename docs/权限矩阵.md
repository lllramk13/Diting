# 权限矩阵(MVP)

对应《协作翻译usecase.md》开发分期中的 MVP 范围。行是操作,列是身份;单元格里的括号是附加条件。

## 通用规则

1. **角色叠加**: Maintainer ⊇ Reviewer ⊇ Translator。上级角色自动拥有下级的全部权限,矩阵中只标注最低要求。
2. **私有项目**: 游客和已登录非成员的所有 ✓ 一律变为 ✗。
3. **禁止自审**: 任何人不能审核自己产生的 revision。例外:Reviewer 使用 edit_and_approve 产生的修订视为已审核,不需要另一人二审(否则两人小组会死锁)。
4. **锁定正交**: `is_locked` 是独立于翻译状态的布尔位,由 Maintainer 设置;锁定的条目连任务负责人也不能编辑。(待确认)
5. **已登录非成员**: MVP 阶段与游客权限完全相同;单独立一列是为 Phase 2 的评论、修改建议和申请加入预留。

## 翻译

| 操作 | 游客 | 登录非成员 | Translator | Reviewer | Maintainer |
|---|---|---|---|---|---|
| 编辑任务内条目 | ✗ | ✗ | ✓(仅自己任务) | ✓(仅自己任务) | ✓(任意条目) |
| 编辑未指派条目 | ✗ | ✗ | ✗ | ✗ | ✓ |
| 编辑 is_locked 条目 | ✗ | ✗ | ✗ | ✗ | ✓(需先解锁) |
| 提交条目审核 | ✗ | ✗ | ✓(仅自己任务) | ✓(仅自己任务) | ✓ |

> Reviewer 编辑权与 Translator 相同:审核能力不等于随意改别人任务的权力,想改走 edit_and_approve。
> 未指派条目只有 Maintainer 能直接改,用于修突发小错;正常流程应先建任务。
